# CONTRIBUTING.md Update Rules

## Purpose

CONTRIBUTING.md guides external and future contributors on how to work with this project. Keep it welcoming, accurate, and comprehensive.

## Required Sections (maintain this order)

1. **Welcome / Introduction** - Brief welcoming message
2. **Development Setup** - How to clone, install prerequisites, and build
3. **Project Structure Overview** - Brief description of key directories
4. **Coding Standards** - Language-specific conventions, commenting requirements
5. **Commit Convention** - Commit message format and guidelines
6. **Branching Strategy** - Branch naming and workflow
7. **Pull Request Process** - How to submit and what reviewers look for
8. **Documentation Requirements** - What docs must be updated with code changes
9. **Testing** - How to run tests and what coverage is expected
10. **Code of Conduct** - Expected behavior (or link to separate file)

## When to Update CONTRIBUTING.md

- Development setup steps change (new tools, new dependencies)
- Coding standards or conventions are established or modified
- The build process changes
- Testing framework or requirements are added
- Branch naming or PR process changes
- New documentation requirements are introduced

## Style Guidelines

- Write in second person ("you") and keep tone welcoming
- Include exact commands for setup steps (copy-paste ready)
- Explain the "why" behind conventions, not just the "what"
- Mark sections as "TBD" rather than omitting them if details aren't finalized yet
